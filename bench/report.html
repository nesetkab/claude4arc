arc-browser vs ego-lite vs Claude for Chrome

Both measured tools passed all 14 tasks, verified by the benchmark server rather than by the agents. After ten rounds of changes, arc-browser now finishes the same agent run in about 50 s (49.4 s and 51.7 s in the last two runs), against 195 s for ego-lite, with one browser call instead of 33 tool calls. ego-lite ran once with its stock skill, while arc-browser was tuned against these same tasks, so treat the gap as an upper bound. ego-lite is faster on single clicks and popups in the scripted run. Claude for Chrome could not run: its extension needs a signed-in Claude account in Chrome.

Agent run: 14 tasks, one fresh subagent per tool

Each subagent received only its tool's skill and the same instructions: 10 local fixtures (forms, cross-origin iframe, confirm dialog, virtual list, drag and drop, popup, code editor, closed shadow DOM, delayed content, hover menu) and 4 real-web lookups.

Can the agent run get faster?

Every row is a fresh subagent with the same instructions. Between runs, arc-browser gained speed rules, selectors that work without looking first (label targets, automatic search in cross-origin frames, exact-text preference), a faster virtual-list seek, a section reader, and a batch command that runs one chain per line with per-line timing and closes the task by itself. v7 exposed a seek bug that v9 fixed. v8 had the first seek fix but still spent a separate call on finish. In-task time is the sum of the agents' own per-task spans; the rest of the total is fixed overhead for every tool (loading the skill, the required timestamp calls, writing the report).

Method and caveats

Verification. Every fixture page reports success to a local benchmark server, which logs the tool, the task, and the submitted value. All fixture results for every run shown are in that log with the expected values. The 4 web answers match the pages (55.845, "Hello World!", "Y Combinator", the MDN return value).

Agent timings. Total time, tokens, and tool calls come from the Claude Code harness. The agents also reported per-task timestamps, but those are not shown as a chart: ego-lite's three web lookups under one second suggest some start timestamps were taken after the page had loaded.

Scripted timings. The scripted runs remove model thinking and measure the tools. The virtual-list task scrolls programmatically in both scripts. The code-editor task uses each tool's native path: arc-browser's editor API, and ego-lite's select-all and paste.

Claude for Chrome. Google Chrome was installed for the run, but the Claude extension must be added from the Chrome Web Store and signed in by the account owner. The chart keeps its column empty and marked, rather than filling it with estimates.
