claude4arc vs ego-lite vs Claude for Chrome

On 14 held-out tasks, with three runs per tool, a Claude Code agent finished in 60 s with claude4arc, 200 s with ego-lite, and 241 s with Claude for Chrome, with 4.3, 36.0, and 69.7 tool calls and 0.18M, 2.19M, and 3.83M tokens read. Every run passed all 14 tasks. The benchmark server checked the 10 fixture results of each run (90 in all); the 36 web-lookup answers are the agents' own reports, which gave the same answers in all nine runs and match the pages. The claude4arc runs are from October 12 at commit b100edd; the other two tools ran in September and were not rerun. The sections below the held-out table cover the original 14 tasks, which claude4arc was tuned on across twelve runs (plus one on Sonnet), so treat those gaps as an upper bound. In the scripted run without a model, ego-lite is faster on six of the ten fixtures, mostly single clicks and the popup.

Can the agent run get faster?

Every row is a fresh subagent with the same instructions. Between runs, claude4arc gained speed rules, selectors that work without looking first (label targets, automatic search in cross-origin frames, exact-text preference), a faster virtual-list seek, a section reader, and a batch command that runs one chain per line with per-line timing and closes the task by itself. v7 exposed a seek bug that v9 fixed. v8 had the first seek fix but still spent a separate call on finish. v12 is a check after the skill was cut by 40%; its harness context size was not recorded, and its B2 retry overlaps later tasks, so its in-task sum counts some seconds twice. In-task time is the sum of the agents' own per-task spans; the rest of the total is fixed overhead for every tool (loading the skill, the required timestamp calls, writing the report).

Method and caveats

Verification. Every fixture page reports success to a local benchmark server, which logs the run, the task, and the submitted value, and node bench/verify.js checks those values against the expected ones. All fixture results for every run shown pass. The server does not see the web lookups: those answers are the agents' own reports, compared against the pages. On the original tasks they are 55.845, "Hello World!", "Y Combinator", and the MDN return value. On the held-out tasks (W5–W8) they are Guido van Rossum, "I'm a teapot" (418), the MIT license, and "My YC app: Dropbox - Throw away your USB drive", the same in every held-out run, including the earlier claude4arc runs, apart from wording such as "418 I'm a teapot" or just "MIT".

Tokens. "Tokens read" is the sum of input tokens over every model turn, from the agents' transcripts; each turn re-reads the conversation, so it tracks cost. "Context tokens" is the harness figure: the size of the agent's context at the end, mostly the fixed system prompt, skill, and instructions.

Agent timings. Total time, tokens, and tool calls come from the Claude Code harness. The agents also reported per-task timestamps, but those are not shown as a chart: ego-lite's three web lookups under one second suggest some start timestamps were taken after the page had loaded.

Scripted timings. The scripted runs remove model thinking and measure the tools. The virtual-list task scrolls programmatically in both scripts. The code-editor task uses each tool's native path: claude4arc's editor API, and ego-lite's select-all and paste.

Claude for Chrome. The official extension ran in Google Chrome, signed in by the account owner, through its MCP tools. On the original tasks it passed every task, but with workarounds its agent chose: it replaced window.confirm through JavaScript because a native dialog blocks the tool, it opened the popup's URL in a new tab because the popup window was outside its tab group, and it used the Tab key inside the cross-origin iframe because clicks there did not register. On the held-out tasks it again passed everything, but clicks and typing by element reference often did not register (H1, H2, H3, H4, H7), so it fell back to coordinate clicks or form_input; its page readers could not see inside the iframe on H9, so it worked from screenshot coordinates; and in one run it read the Wikipedia infobox and the GitHub sidebar with JavaScript after its find tool missed them (W5, W7). It has no scripted API, so the scripted charts leave its column empty.
